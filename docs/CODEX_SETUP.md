# Develop GaitLab with Codex — local, cloud, and physical device

The **Git repository is the source of truth**. No ZIP extraction is needed. This repository already contains the Flutter application, pure-Dart gait engine, CSV/JSON exports, QA tools, public-dataset replay, and CI. Native Android/iOS runners are deliberately generated by the guarded bootstrap script until they are built and reviewed for commit.

## Recommended model
- Normal Flutter development: **GPT-6.1 Sol, High** (if offered in your Codex model selector).
- Trivial cleanups: Sol Medium; independent gait-algorithm and test audit: **GPT-6 Astra, High** (if available).
- `.codex/config.toml` expresses the project default, but personal settings, availability and trust can override it. Do not assume model choice guarantees scientific validity.

## First clone on macOS
1. Install Flutter **3.47.7+**, Android Studio + Android SDK, and Xcode + CocoaPods for iOS (per official Flutter install guides).
2. Clone and verify:

```bash
git clone https://github.com/sweslo17/GaitLab.git
cd GaitLab
git switch -c develop
flutter doctor -v
bash scripts/bootstrap.sh
bash scripts/verify_local.sh
flutter devices
flutter run -d YOUR_DEVICE_ID
```

The bootstrap is repeatable. On macOS it creates only **missing** `android/` and `ios/` directories in a temporary project and copies those runners into the repo; it does not regenerate `lib/`, `test/`, README, or the project pubspec. Review generated runners and keep any necessary native configuration under source control after validating them.

If you want a Python-only smoke check: `bash scripts/verify_local.sh --python-only`. This is **not** Flutter verification.

## Physical phone test
- Android: enable developer options + USB debugging, authorize this Mac, run `flutter devices` then `flutter run -d ID`.
- iPhone: connect and trust the Mac, install Xcode, select a signing team in the generated `ios/Runner.xcworkspace`, then `flutter run -d ID`. Free Apple signing can suffice for local development; no App Store release required.
- Use a **tight running belt** (ideally centered at rear waist); keep placement consistent.
- Collect 10 s standing, 30 s walking and ≥2 min jogging; manually count or synchronously film step events; repeat across speed/device/belt tightness.
- Export all six session files; check `python3 tools/analyze_session.py /path/to/session --out qa.json`.
- Inspect dropped samples and event timestamps before trusting cadence. Do not infer real footstrike timing or health conditions.

## Codex Cloud (Linux)
In Codex Cloud create an environment connected to `sweslo17/GaitLab`. It can inspect and prepare dependencies itself. If a custom install script is requested, use:

```bash
bash scripts/codex_cloud_setup.sh
```

This script pins Flutter **3.47.7** under `~/.cache/gaitlab`, adds `flutter`/`dart` links in `~/.local/bin`, creates the Android runner and runs Python, analyzer and Dart tests. It requires network access in the setup phase and an installed `git` and `python3`. Cloud image setup may still need an Android SDK to build APKs. **No macOS/Xcode/iPhone is present in the Linux environment**.

Save/publish the **Codex Cloud environment** only once setup checks succeed. Publishing the environment does **not** release the App. Cloud work can run tests/replays without any GitHub app release; push to a development branch only when you want cloud to see local changes.

## Verification ladder
1. Python tests + shell syntax; 2. `flutter analyze` + `flutter test`; 3. pinned public running/sitting dataset replay via production Dart; 4. debug APK + iOS simulator build; 5. USB/Wi-Fi physical-device recording and CSV/JSON integrity; 6. synchronized foot-contact references and held-out participant/device accuracy.

Never collapse these stages into a single "all tests pass". See `VALIDATION.md` and `PUBLIC_DATASETS.md`.
