# Android 關屏持續錄製計畫

使用者明確要求開始後關閉螢幕仍持續記錄，這取代 v0.4 Android 前景限定政策。iOS 仍保持原本前景限定，不宣稱未測試的平台支援。

架構：原始 sensors_plus 取得與純 Dart 訊號計算不變。Android 原生 health 前景服務維持程序優先序及 CPU partial wake lock；Dart 平台橋接負責啟停與失敗清理。螢幕不再強制常亮。服務不自動重啟、不支援強制停止或程序死亡後恢復。

- [x] Android 服務在啟動成功後才回傳 active，顯示持續通知。需要的前景服務類型及正常感測權限明列於 manifest，不增加定位或心率權限。
- [x] Android 13 通知權限在使用者按開始後請求；拒絕不造成崩潰，也不謊報通知可見。
- [x] Android 關屏／背景不停止 Dart 感測訂閱，維持缺樣診斷與定期 flush。其他平台保留安全停止。
- [x] 正常停止、啟動失敗、Activity 銷毀及 task 移除均釋放服務與 CPU lock，不留下空服務。
- [x] 測試橋接的 active 確認、失敗、取消競爭與生命週期，完整 Flutter 檢查及 Android build。
- [x] 安裝到連接的 Samsung 手機，量測至少 60 秒鎖屏期間的原始樣本連續性、服務狀態與停止後鎖釋放。區分 USB 連接下的煙霧測試與長時間實跑。

四項功能狀態：動作分類未實作；身體方向校正後三向分布未實作；旋轉未實作而波形規律性已有；前後段比較已有但並非 GPS 配速配對。此任務先完成明確要求的關屏錄製，不把未實作項目描述成完成。

實機證據：Samsung Android 16，在 USB 連線下非互動關屏 63 秒，兩個原始串流持續寫入；通知停止並儲存成功，服務及 CPU lock 已釋放。這是短時間煙霧測試，未測拔線耐久、電量消耗及程序死亡恢復。詳見 VALIDATION.md。
